Seguridad Web Explicada Fácil

¿Qué significan CSRF, Validación de Sesión y Escalamiento de Privilegios en tu sistema? Entiéndelo con analogías de la vida real.

1. ¿Qué es CSRF y las Peticiones Falsificadas?

Cross-Site Request Forgery (Falsificación de Petición en Sitios Cruzados)
La Metáfora de la Vida Real: "El Cheque en Blanco"

Imagina que vas al banco y te identificas en ventanilla con tu documento. Mientras estás ahí hablando, alguien te entrega un papel que dice "Firma aquí para donar $1", pero por debajo el papel dice "Transfiere todos tus ahorros a mi cuenta". Como el banco ya sabe quién eres tú, ¡la orden se ejecutaría con tu nombre si no existiera una confirmación secreta!

¿Cómo ocurre en la computadora? Si tienes abierta tu sesión de Administrador en una pestaña y en otra pestaña abres un enlace malicioso, esa página externa puede intentar enviar órdenes a tu sistema haciéndose pasar por ti.

1
Abres el Formulario
El servidor genera un código secreto único (token) y lo esconde dentro de tu formulario con Csrf::tokenField().
2
Envías los Cambios
Al hacer clic en "Guardar Permisos", tu navegador envía ese código secreto junto con los datos.
3
Verificación Estricta
El controlador ejecuta CsrfMiddleware::verify(). Si una web externa intentó atacar, no tiene el token y el sistema la frena de inmediato.
// 1. En la vista (HTML): Inserta el sello secreto invisible
<form action="index.php?action=permisos_update" method="POST">
    <?php echo Csrf::tokenField(); ?>

// 2. En el controlador (PHP): Exige el sello antes de hacer nada
try {
    CsrfMiddleware::verify();
} catch (Exception $e) {
    flash('error', 'Token de seguridad inválido.');
    exit();
}

2. Validación Estricta de Sesión

Control de Acceso basado en Roles
La Metáfora de la Vida Real: "El Guardia en la Puerta VIP"

No basta con que no pongas el cartel de "Zona VIP" a la vista de todos. Si alguien descubre la puerta trasera o el pasillo, un guardia de seguridad debe estar parado en la puerta exigiendo el brazalete VIP para dejar pasar.

Un usuario con rol normal (por ejemplo, un operador o recepcionista) podría intentar escribir manualmente en la barra de direcciones de su navegador:
http://localhost/php_system/index.php?action=permisos

// PermisoController.php - Línea 16: El guardia revisa el brazalete
if (strtolower($_SESSION['tipousuario']) !== 'administrador') {
    flash('error', 'No tiene permisos para acceder a este módulo.');
    header("Location: dashboard.php");
    exit(); // Expulsado inmediatamente
}

3. Escalamiento de Privilegios & Roles Reservados

Impedir modificar 'administrador' y 'socio'
¿Qué es "Escalar Privilegios"?

Es cuando un usuario corriente busca la manera de "subir de nivel" sin autorización, por ejemplo, intentar otorgarse a sí mismo poderes de Administrador, o sabotear el sistema quitándole los poderes al verdadero Administrador.

El Truco del "Inspeccionar Elemento"
Alguien con conocimientos básicos puede abrir las herramientas de desarrollador (F12) y alterar el campo oculto del formulario para poner name="tipousuario" value="administrador" y desmarcar todas las casillas.
La Protección en el Servidor
Tu código en PHP no confía en lo que mande el navegador. Revisa explícitamente que nadie pueda alterar al 'administrador' ni al 'socio'.
// PermisoController.php - Línea 40: Bloqueo explícito de roles vitales
if (!empty($tipousuario) &&
    strtolower($tipousuario) !== 'administrador' &&
    strtolower($tipousuario) !== 'socio') {
    // Solo permite modificar roles normales (asistente, cajero, etc.)
    $this->permisoModel->updatePermisos($tipousuario, $modulos_seleccionados);
} else {
    flash('warning', 'No se puede modificar este tipo de usuario.');
}

Tu Sistema está Blindado

Gracias a estas tres capas, nadie puede engañarte desde otra web (CSRF), nadie puede entrar sin ser Administrador (Sesión) y nadie puede romper el rol principal ni auto-ascenderse (Escalamiento de Privilegios).
