01

Ficha Técnica & Planteamiento del Problema

🎯
Propósito

El Reto Institucional

Garantizar la gestión unificada de afiliados, eliminar el fraude o suplantación en asambleas mediante biometría de huella en vivo, y permitir la participación democrática con voto remoto cifrado y trazable.

⚙️
Stack

Especificaciones Técnicas

Backend: PHP 8.1 nativo (sin frameworks monolíticos).
Base de Datos: MySQL / MariaDB mediante transacciones PDO.
Biometría: SDK Nativo C++ / Python Bridge (FPModule).
Seguridad: Tokens efímeros, RBAC dinámico y CSRF.

02

Patrón Arquitectónico & Diseño de Software

El sistema prescinde de cajas negras y adopta una implementación rigurosa de patrones de diseño de nivel empresarial:

🗄️
src/Models/

Modelos (Active Record / DAO)

Encapsulan las reglas de negocio y consultas con PDO::prepare(). Clases como Votacion, Socio, Huella y Permiso administran su persistencia e integridad relacional.

⚡
src/Controllers/

Controladores (Orquestadores)

Interceptan las peticiones, verifican tokens CSRF y autorizaciones, solicitan transacciones a los modelos y despachan la salida (HTML renderizado o JSON para llamadas AJAX).

🛡️
public/index.php

Front Controller & Middleware

Punto de entrada universal. Ningún archivo interno puede ser consultado de forma aislada. Controla la sesión, verifica la lista blanca de rutas públicas y ejecuta el RBAC antes de invocar cualquier controlador.

03

Ciclo de Vida de una Petición (Request Lifecycle)

1

Front Controller (public/index.php)

Recibe la solicitud HTTP con el parámetro ?action=nombre_accion. Carga el archivo src/bootstrap.php que inicializa variables de entorno (.env), configuración de sesiones seguras y autoloader PSR-4 compatible.

2

Capa de Seguridad, Sesión & RBAC Dinámico

Evalúa si la acción es pública. Si es privada, exige sesión activa. Si el usuario es de tipo SOCIO, restringe las acciones a su catálogo permitido. Si es otro rol, consulta en tiempo real con Permiso::hasAccess() contra la base de datos.

3

Ejecución en Controlador & Middleware de Mutación

Si la petición es de tipo POST, se evalúa obligatoriamente CsrfMiddleware::verify() para evitar ataques de falsificación de peticiones. El controlador coordina la lógica requerida.

4

Persistencia en Base de Datos (PDO Prepared)

El modelo ejecuta operaciones SQL estrictamente parametrizadas con transacciones ACID (beginTransaction, commit, rollBack) para garantizar atomicidad.

5

Renderizado de Vista o Respuesta JSON

Para peticiones web estándar, inyecta las variables en plantillas situadas en src/Views/. Para peticiones AJAX (como verificación de huella o IA), devuelve payloads JSON tipados.

04

Módulo de Sufragio & Voto Remoto Criptográfico

🗳️
Voto Presencial

Transaccionalidad ACID

Al registrar la boleta, se inicia una transacción en MySQL. Cada voto individual por postulado se vincula al sufragio global. Si falla un solo registro, se revierte todo con rollBack() para evitar votos huérfanos.

🌐
Voto Remoto

Tokens Efímeros de Un Solo Uso

Se genera un token criptográfico no predecible asociado a la acción con TTL (tiempo de vida limitado). El enlace se despacha por correo mediante PHPMailer (SMTP TLS). Al emitir el voto, el token se autodestruye inmediatamente en la BD.

📊
Escrutinio Paramétrico

Quórum y Reglas de Aceptación

El sistema valida que la cantidad de votantes únicos alcance el votacion_minimo_votantes y que los candidatos superen el votacion_porcentaje_aceptacion configurado antes de emitir actas oficiales de proclamación.

05

Arquitectura de Integración Hardware-Web (Biometría)

🔌
Hardware Bridge

Patrón de Puente Local

Debido al sandbox del navegador que prohíbe el acceso directo a puertos USB, se implementó un Daemon/Microservicio Local en puerto 8888 (manejado por PuenteController y scripts de SDK) que dialoga con los drivers del lector.

🖐️
Templates

Validación de Huella & Redundancia

El sistema rechaza templates corruptos menores a 100 bytes (para evitar falsos positivos por suciedad o ruido) y exige obligatoriamente enrolar dos huellas distintas (ej. índice derecho e izquierdo) con verificación de no coincidencia idéntica.

07

Ciberseguridad y Mitigación de Vulnerabilidades (OWASP Top 10)

Vulnerabilidad (OWASP) Riesgo Potencial Mecanismo de Defensa en el Código
SQL Injection (SQLi) Robo o alteración de base de datos. 100% de consultas preparadas: Abstracción total mediante PDO y vinculación de parámetros con bindValue/bindParam en todos los modelos.
Cross-Site Request Forgery Acciones involuntarias ejecutadas por un usuario autenticado. CsrfMiddleware: Generación y validación de tokens criptográficos aleatorios por sesión exigidos en cada petición POST.
Insecure Direct Object Reference Un socio vota a nombre de otra acción alterando el formulario. Control de Pertenencia IDOR: En VotacionController::votar() se comprueba que la acción enviada pertenezca a la lista de acciones activas vinculadas a su cédula.
Session Hijacking Robo de cookies de sesión mediante XSS de red. Cookies Endurecidas: En bootstrap.php se configuran flags httponly = true, SameSite = Lax, secure en HTTPS y expiración estricta por SESSION_LIFETIME.
Broken Access Control Escalamiento vertical u horizontal de privilegios por URL. RBAC Dinámico: Matriz relacional administrable en permisos_tipousuario interceptada en el Front Controller.
08

Preguntas Clave del Jurado Evaluador & Argumentación

¿Por qué desarrollaron el sistema en PHP nativo en lugar de utilizar un framework como Laravel? ▼
Esta decisión responde a tres justificaciones fundamentales de ingeniería:
"1. Rendimiento & Baja Latencia: La comunicación con el daemon biométrico USB local y el procesamiento de sufragios en tiempo real requieren una sobrecarga mínima de CPU y memoria.
2. Reducción de Superficie de Ataque: Se elimina la dependencia de cientos de paquetes externos de terceros sujetos a vulnerabilidades en la cadena de suministro.
3. Demostración de Competencias de Grado: Construir el enrutador, el middleware de seguridad, el motor RBAC y la capa de abstracción PDO desde cero demuestra el dominio completo de los protocolos web y de la arquitectura de software."
¿Cómo se garantiza que un socio no vote dos veces y que el voto sea secreto? ▼
Se implementa segregación de responsabilidades:
"El sistema comprueba mediante el método yaVoto($accion) si la acción ya emitió su sufragio en el periodo activo. El registro del voto disocia la identidad del elector de la papeleta final consolidada. En el caso del voto remoto, el enlace utiliza un token criptográfico efímero de un solo uso que se autodestruye inmediatamente después de confirmar la transacción."
¿Qué sucede si hay una caída de energía o interrupción eléctrica a mitad de una votación? ▼
Se garantiza la consistencia del sistema mediante la propiedad de Atomicidad (ACID):
"El guardado de votos se ejecuta bajo un bloque $this->db->beginTransaction(). Si ocurre un corte de energía, falla de red o error de servidor antes de completar todos los postulados, MySQL ejecuta un rollback automático al expirar la conexión. La base de datos queda intacta, no se registran votos parciales y el socio puede votar nuevamente al restablecer el servicio."
¿Cómo puede un navegador web leer una huella dactilar de un lector USB? ▼
Se resolvió implementando el patrón Architectural Hardware Bridge:
"Dado que los navegadores web por políticas de seguridad operan en una 'sandbox' y no pueden acceder al bus USB de la máquina, se configuró un daemon de comunicación local en el puerto 8888. La aplicación web realiza una petición asíncrona local por AJAX al daemon; este se comunica con las librerías dinámicas (DLL/SDK) del sensor, extrae las minucias de la huella en un template matemático seguro y lo devuelve al frontend para su contrastación."
